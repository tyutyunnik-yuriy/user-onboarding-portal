# Кадровые IT-заявки

Проект включает:

- веб-форму заявки с двумя типами: подключение и увольнение;
- заявку на изменение прав действующего сотрудника;
- серверную проверку обязательных полей;
- портал администратора со списком заявок, поиском, фильтрами и сменой статуса;
- прием заявок через Telegram-бота;
- хранение заявок, сотрудников и справочников в PostgreSQL;
- одноразовую миграцию старых JSON-данных в PostgreSQL.

## Справочники

В портале администратора есть вкладка `Справочники`. Там можно редактировать:

- отделы;
- должности;
- бизнес-юниты;
- уровни доступа;
- системы для подключения.

Эти значения используются в формах заявок и в карточке сотрудника.

Должности привязываются к отделам. В заявке и карточке сотрудника после выбора отдела список должностей автоматически сужается до должностей этого отдела.

Отделы привязываются к бизнес-юнитам. В справочнике `Отделы` у каждого отдела можно выбрать один или несколько бизнес-юнитов, где этот отдел существует. В форме заявки сначала выбирается бизнес-юнит, затем список отделов сужается до отделов этого бизнес-юнита.

Системы привязываются к бизнес-юнитам. В справочнике `Системы` у каждого значения выбирается один или несколько бизнес-юнитов, для которых оно доступно. В заявке на подключение и в карточке сотрудника показываются только системы выбранного бизнес-юнита. Если у сотрудника уже есть система вне текущего набора бизнес-юнита, она остается видимой как уже назначенная, чтобы ее не потерять при редактировании.

`Руководители` показываются в справочниках отдельным списком, но напрямую там не редактируются. Руководитель — это сотрудник с включенным признаком `Руководитель отдела`; ФИО, телефон и бизнес-юнит берутся из карточки сотрудника.

При создании заявки на подключение руководитель автоматически подставляется по выбранной паре `Бизнес-юнит + Отдел`: система ищет сотрудника-руководителя этого отдела, у которого выбран соответствующий бизнес-юнит. Один руководитель может отвечать за несколько бизнес-юнитов.

## Сотрудники

Для заявки на увольнение сотрудник выбирается из базы PostgreSQL. После выбора форма автоматически подтягивает:

- фамилию, имя и отчество;
- почту;
- отдел;
- должность;
- руководителя.

В заявке сохраняется снимок этих данных, чтобы история не менялась задним числом.

В портале администратора есть вкладка `Сотрудники`. Там можно:

- добавить нового сотрудника;
- изменить фамилию, имя, отчество, почту, телефон, Telegram chat ID, отдел, бизнес-юнит, должность и руководителя;
- указать уровень доступа и системы, которые есть у сотрудника;
- отметить сотрудника как руководителя отдела;
- отметить сотрудника уволенным;
- вернуть сотрудника в активные.

Уволенные сотрудники остаются в базе для истории, но не показываются в форме новой заявки на увольнение. При увольнении список систем на отключение берется из карточки выбранного сотрудника.

Списки руководителей в заявках и карточках сотрудников строятся из сотрудников с признаком `Руководитель отдела`.

Если у руководителя заполнен `Telegram chat ID`, после создания заявки бот отправит ему сообщение с кнопками `Согласовать` и `Отклонить`. Нажатие кнопки меняет статус заявки в портале.

Чтобы узнать `Telegram chat ID`, руководитель должен написать боту `/start`. Бот ответит строкой `Ваш Telegram chat ID: ...`; это значение нужно внести в карточку сотрудника-руководителя.

## Изменение прав

В форме заявки есть тип `Изменение прав сотрудника`. После выбора сотрудника форма показывает:

- текущий уровень доступа;
- системы, которые уже есть у сотрудника;
- системы из справочника, которые можно добавить.

При переводе такой заявки в статус `Выполнена` карточка сотрудника обновляется автоматически.

## Запуск

### 1. Установить зависимости

```bash
./bin/install-deps
```

### 2. Поднять PostgreSQL

```bash
./bin/start-postgres
```

### 3. Задать строку подключения

```bash
export DATABASE_URL=postgres://hr_app:hr_app_password@localhost:5432/hr_requests
```

### 4. Создать таблицы

```bash
./bin/setup-db
```

Команда также добавляет стартовые справочники и несколько тестовых сотрудников, чтобы заявка на увольнение сразу могла подтянуть сотрудника из базы.

### 5. При необходимости перенести старые JSON-данные

```bash
/Users/yuriy/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/migrate-json-to-postgres.js
```

### 6. Запустить приложение

```bash
./bin/start
```

После запуска:

- форма заявки: http://localhost:3002/
- портал администратора: http://localhost:3002/admin.html
- логин администратора: `admin`
- пароль администратора локально: `admin123`

На реальном сервере обязательно задайте свои значения:

```bash
export ADMIN_USER=your-admin
export ADMIN_PASSWORD=long-random-password
```

В HTML-форме пароль намеренно не подставляется автоматически.

## Статусы заявок

В портале используются статусы:

- `Новая`;
- `В работе`;
- `Согласована`;
- `Отклонена`;
- `Выполнена`.

Заявку можно выполнить только после согласования. Это защищает процесс от случайного выполнения несогласованной заявки.

## Запуск через Docker Compose

После установки Docker Desktop можно поднять базу и приложение вместе:

```bash
ADMIN_USER=admin ADMIN_PASSWORD='replace-with-a-long-random-password' docker compose up -d --build
```

Приложение само дождется PostgreSQL, применит схему базы и запустится на:

- http://localhost:3002/
- http://localhost:3002/admin.html

Для живой публикации поверх этого обычно ставится reverse proxy с HTTPS: например Nginx или Caddy.

## Telegram

1. Создайте бота через BotFather.
2. Запустите проект с токеном:

```bash
TELEGRAM_BOT_TOKEN=123:abc TELEGRAM_ADMIN_CHAT_ID=123456 node server.js
```

3. Отправьте боту заявку в одном из форматов.

Подключение:

```text
Тип: подключение
ФИО: Иван Иванов
Почта: ivan@example.com
Телефон: +380501112233
Отдел: Продажи
Должность: Менеджер
Руководитель: Петр Петров
Дата: 2026-06-10
Доступ: Базовый
Системы: CRM, Корпоративная почта
Комментарий: Нужен VPN
```

Увольнение:

```text
Тип: увольнение
Сотрудник: Иван Иванов
Почта сотрудника: ivan@example.com
Отдел: Продажи
Руководитель: Петр Петров
Дата увольнения: 2026-06-20
Отключить: В день увольнения в 18:00
Передать: Петр Петров
Действия: Почта, CRM, VPN, Передать файлы
Комментарий: Уволить после окончания рабочего дня
```

Если `TELEGRAM_ADMIN_CHAT_ID` задан, администратор получит уведомление о новой заявке.
